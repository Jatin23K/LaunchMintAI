5) Backend architecture & components

Keep it modular and observable.

Recommended stack

Backend framework: Node.js (NestJS) or Python (FastAPI). Use TypeScript if Node.

Datastore: PostgreSQL (primary), Redis (cache, job queue), S3-compatible storage for files.

Search & embeddings: OpenSearch / Elastic or vector DB (Milvus, Weaviate, or Pinecone).

ML / LLM infra: Calls to cloud LLM APIs (OpenAI/GWEN/Anthropic/etc.), local LLM serving optional for privacy (Phase 2).

Worker queue: Celery/RQ/BullMQ for async processing (OCR, scraping, long LLM jobs).

OCR: PaddleOCR pipeline (you prefer it) running in workers or serverless GPUs.

Scraping: headless browser pool (Playwright) with rate limit and IP rotation via proxies.

Embedding pipeline: create embeddings for docs, snippets, competitor snapshots.

Containerization: Docker + Kubernetes (K8s) for production scaling.

Microservices

API Gateway (auth, routing)

Extensions service (pluggable handlers per extension)

Document ingestion service (OCR, parsing)

Embedding & search service

Job orchestration service (saga pattern for multi-step runs)

Billing service (Stripe integration)

Notifications service (email/Slack/webhook)

Why microservices? Because each extension has different resource needs and scaling patterns.

6) LLM/AI design & prompts

This is where most teams fail.

Strategy

Use a layered approach: retrieval-augmented generation (RAG) + tool-augmented LLMs.

Store source snippets + metadata; always attach provenance to claims.

Break complex tasks into small sub-prompts; validate outputs against rules & heuristics.

Use system prompts that enforce tone and structure (e.g., “Produce a 3-section output: Summary, Evidence, Actions”).

Keep a prompt versioning table (so outputs are repeatable & auditable).

Model plan

MVP: Use 1–2 high-quality APIs for reasoning (e.g., GPT-4o style model or equivalent) + embeddings from a fast, cheaper model.

Phase 2: Add local LLM fallback for privacy-sensitive work (fine-tuned smaller LLMs).

Cost control: set max tokens, use short prompts + streaming for large outputs.

Validation

Build a “validator agent” for each extension that checks outputs vs. rules (e.g., competitor list must include X if Y exists).

For Document Intelligence: run extraction + compare to source via F1 metrics.

20) Common failure modes & how to prevent them (be paranoid)

Hallucinations: Attach provenance, use validator agents, human-in-loop for critical outputs.

Credit-card shock: Implement token/cost visibility and throttling.

Scraping throttle/IP ban: Use robust proxying, respect robots.txt, provide fallbacks for unavailable pages.

Bad UX from long jobs: streaming responses, progressive rendering, job logs.

Data leaks across tenants: strict tenant isolation + encryption + tests.
